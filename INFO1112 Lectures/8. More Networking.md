## 1. Recap: Ring Topology & Media Access Control

- **Logical Ring Topology:** Nodes are arranged logically in a continuous circular loop.
- **Relay Mechanism:** Messages circulate sequentially (e.g., clockwise). Intermediate nodes inspect the destination address; if it does not match their own IP, they relay the message untouched to the next node.
- **Media Access Philosophy:** "When person A is speaking, everyone else must listen."
- **Collision Prevention:** Uses a deterministic token-passing mechanism (like passing a physical microphone). Only the node holding the token may transmit data.
- **Scalability:** Because collisions are strictly prevented ($\text{Collisions} = 0$), large amounts of data can be reliably distributed across wide geographic areas (e.g., connecting metropolitan networks / cities).

## 2. Bus Topology & Contention-Based Access

### Architecture
- All devices ([[Node|Nodes]]) connect to a single shared physical transmission line called the ==**Backbone**== (common shared medium).
- **Analogy:** Cable television (CATV), where multiple household subscribers branch off a single shared coaxial backbone carrying broadcast signals.

```text
       [Node 1]           [Node 2]           [Node 3]
          │                  │                  │
 ═════════╧══════════════════╧══════════════════╧═════════  <── Shared Backbone
```

### Transmission Behavior & Contention
- Any node can attempt to communicate at any time.
- **Carrier Sense:** Before transmitting, a node first listens to the backbone to check whether a carrier signal (message) is currently present.
  - If **no signal is detected** $\rightarrow$ the node assumes the medium is free and begins transmitting.
  - If **a signal is detected** $\rightarrow$ the node waits.

### Duplex Modes
- ==**Half-Duplex:**== A node can either send OR receive data at any given moment, but **not both simultaneously** (e.g., a walkie-talkie where you press a button to talk and release to listen). If Node 3 is transmitting to Node 2, Node 2 is listening, and no other node may speak.
- ==**Full-Duplex:**== Nodes can send AND receive data simultaneously (e.g., a telephone call where both parties can talk and listen at the same time).

### Collisions & CSMA/CD
- **How Collisions Happen:** If Node 1 and Node 3 both check the backbone at the exact same moment, both detect silence (no active signal). Both start transmitting simultaneously $\rightarrow$ their electrical signals collide on the shared backbone, corrupting both messages.
- ==**CSMA/CD (Carrier Sense Multiple Access with Collision Detection):**==
  - The philosophy of bus networks is **not** collision prevention; rather, it is:
    $$\text{Detect collision} \implies \text{Take immediate corrective recovery action}$$
- ==**Jamming Signal:**==
  - When any transmitting node detects a collision on the wire, it immediately aborts transmission and emits a high-frequency **Jamming Signal** across the backbone.
  - A jamming signal acts as an explicit network-wide announcement ("**SHUT UP**"), notifying all devices that an accident has occurred.
  - All nodes immediately cease transmitting, wait for a randomized backoff period, and attempt to retransmit later.

### Bus Topology Limitations
- **Scalability Issues:** As more nodes join the bus, the probability of simultaneous transmissions and collisions spikes dramatically, causing performance and throughput to collapse.
- **Difficult Maintenance & Troubleshooting:** Adding or replacing a device requires physically cutting the backbone cable, taking down the **entire network** for the duration of the installation. A single break anywhere along the backbone disables communication for all nodes.

## 3. Star Topology & Modern Switched Networks

### Architecture
- Every device connects individually to a central hardware device known as a ==**Switch**== via its own dedicated cable.

```text
       [Node 1]          [Node 2]
           \                /
            \              /
             ┌────────────┐
             │   SWITCH   │
             │  [Buffer]  │
             └────────────┘
            /              \
           /                \
       [Node 3]          [Node 4]
```

### Key Characteristics & Advantages
1. **Logical Point-to-Point Links:**
   - The connection between each node and the switch is an isolated point-to-point circuit operating under point-to-point principles.
   - **Zero Collisions:** Communication on one cable is completely isolated from other cables.
2. **Full-Duplex Operation:**
   - Every node can send data to the switch and receive data from the switch at the same time without collision.
3. **Switch Buffering & Forwarding:**
   - The switch acts like a central railway station.
   - It possesses internal memory buffers. When Node 1 transmits data destined for Node 4, the switch receives the frames into its buffer. Once Node 4's destination port is ready, the switch selectively forwards the message exclusively to Node 4.
4. **Resilience & Ease of Troubleshooting:**
   - **Plug-and-Play Expansion:** To add a new computer, simply connect an Ethernet cable to an unoccupied switch port. The existing network experiences **zero downtime**.
   - **Isolated Faults:** If Node 3 loses connection or its cable is damaged, only Node 3 goes offline; all other nodes continue communicating unaffected. Troubleshooting is restricted to inspecting Node 3 and its dedicated cable.

## 4. Network Topology Comparison Matrix

| Feature | Ring Topology | Bus Topology | Star Topology |
| :--- | :--- | :--- | :--- |
| **Physical Layout** | Closed circular loop | Single linear backbone cable | Central switch with radiating spokes |
| **Logical Behavior** | Sequential token passing | Shared broadcast medium | Point-to-point switched links |
| **Duplex Mode** | Typically Half-Duplex | Half-Duplex | Full-Duplex |
| **Collision Handling** | **Prevented** (Token-passing) | **Detected** (CSMA/CD + Jamming Signal) | **Negated / Eliminated** (Dedicated switch ports) |
| **Scalability** | High (determinate delay, 0 collisions) | Poor (traffic increases $\rightarrow$ collision storm) | Excellent (add devices via free switch ports) |
| **Impact of Node/Cable Failure** | High (can break loop unless redundant ring) | High (backbone cut halts entire network) | Low (only the failing node is affected) |
| **Primary Use Case** | Metropolitan / city rings, legacy LANs | Cable TV (CATV), legacy coax LANs | Modern enterprise & home LANs |

## 5. Local Area Network (LAN) & Ethernet Standards

### What is a LAN?
- **Definition:** A network contained within a localized geographical boundary, owned and administered by a single individual or organization with a shared goal, resources, or interests (e.g., a home network, a university classroom, an office floor).
- Even a classroom of students sharing ideas through speech (medium: air) conceptually forms a human LAN.

### The Ethernet Standard
- Modern LAN architectures are governed by the **Ethernet** standards (IEEE 802.3).
- The Ethernet standard dictates three fundamental elements:
  1. **Interface Type:** Network Interface Cards (**NICs**) and hardware physical addressing.
  2. **Logical Addressing:** **IP addresses** to uniquely designate nodes on the network.
  3. **Transmission Medium & Compatibility:** Approved physical media (e.g., Cat5e/Cat6 twisted-pair copper cables, fiber optics, switches) ensuring plug-and-play compliance (just like standardized USB ports).

## 6. Physical vs. Logical Addressing: MAC vs. IP

Every connected device on an Ethernet LAN relies on two distinct addressing layers:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   MAC Address (Layer 2 - Hardware)                     │
│  [ Manufacturer ID / OUI: 3 Bytes ] [ Device Serial ID: 3 Bytes ]      │
│  e.g., 00 : 15 : 5d : xx : xx : xx (48 bits / 6 Bytes total)           │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   IP Address (Layer 3 - Logical)                       │
│  [ Network Prefix (Identifies LAN) ] [ Host Identifier (Unique Node) ] │
│  e.g., 192.168.1 . 10 (32 bits / 4 Bytes total in IPv4)               │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. MAC Address (Media Access Control)
- **Nature:** Permanent physical hardware address "burned" directly into the NIC's firmware/circuitry during manufacture.
- **Length:** **48 bits (6 Bytes)**, written as 6 pairs of hexadecimal digits separated by colons (e.g., `00:15:5d:3a:9f:12`).
- **Structure:**
  - **First 3 Bytes (24 bits):** **Manufacturer ID / OUI (Organizationally Unique Identifier)**, assigned globally by the IEEE.
  - **Last 3 Bytes (24 bits):** **Device ID / Serial Number**, assigned by the manufacturer.
- **Global Uniqueness:** No two physical NICs anywhere in the world share the same MAC address.

### 2. IP Address (Internet Protocol)
- **Nature:** Logical software address assigned dynamically or statically to designate a device's current location on a network.
- **Uniqueness Rule:** No two devices residing on the same local network may share the same IP address; doing so creates an IP collision/conflict, making packet routing ambiguous.
- **Structural Analogy (Family Name vs. Given Name):**
  - **Network Address:** Acts like a family surname—shared among all devices belonging to the same local network.
  - **Host Address:** Acts like a personal first name—uniquely distinguishes an individual device within that family group.

## 7. IPv4 Addressing, Subnet Masks & Commands

### IPv4 Structure
- An IPv4 address is **32 bits (4 Bytes)** in length, divided into 4 octets separated by dots ($X.X.X.X$).
- Each octet represents 8 bits:
  $$2^8 = 256 \implies \text{Value range: } [0, 255]$$
- Special octet conventions:
  - `0`: Reserved to designate the **Network ID**.
  - `255`: Reserved to designate the **Broadcast Address**.
  - Usable host range within an octet: `[1, 254]`.

### Subnet Masks
- A ==**Subnet Mask**== indicates how many bits of an IP address represent the network portion versus the host portion.
- **Common `/24` Subnet (`255.255.255.0`):**
  - First 24 bits are all $1\text{s}$ ($\text{Network bits}$): `11111111.11111111.11111111.00000000`.
  - Remaining 8 bits are $0\text{s}$ ($\text{Host bits}$).
  - Example: If Node 1 has IP `1.2.3.4` with mask `255.255.255.0`, its network is `1.2.3`. Node 2 on the same LAN must share `1.2.3.X` (e.g., `1.2.3.5`), where $X \in [1, 254]$ and $X \neq 4$.

### Inspecting Network Addresses in Linux
```bash
# Display all configured network interfaces, IPv4 and IPv6 addresses:
ip addr show

# Display only IPv4 addresses:
ip -4 addr show
```

### Subnetting Case Study: Smartphone Hotspot (`/20` Mask)
- **Scenario:** A smartphone acts as a mobile Wi-Fi hotspot for a PC with smartphone IP `172.26.144.1` and subnet mask `255.255.240.0` (`/20`).
- **Binary Breakdown:**
  - Mask `255.255.240.0` has $8 + 8 + 4 = 20$ network bits:
    $$\underbrace{11111111}_{\text{Octet 1: } 255} . \underbrace{11111111}_{\text{Octet 2: } 255} . \underbrace{1111}_{\text{4 net bits}} \underbrace{0000}_{\text{4 host bits}} . \underbrace{00000000}_{\text{Octet 4: } 8 \text{ host bits}}$$
  - In the 3rd octet, $144_{10} = 10010000_2$.
  - Fixed Network Prefix (first 20 bits): `172.26.1001`
  - Host portion spans the remaining 12 bits:
    - **Lowest host address:** `172.26.1001 0000 . 00000001` = `172.26.144.1` (Smartphone gateway)
    - **First available client IP:** `172.26.1001 0000 . 00000010` = `172.26.144.2` (Allocated to PC)
    - **Highest usable host IP:** `172.26.1001 1111 . 11111110` = `172.26.159.254`
    - **Subnet broadcast IP:** `172.26.1001 1111 . 11111111` = `172.26.159.255`
- Any client device connected to this hotspot must receive an IP within `172.26.144.2` – `172.26.159.254`.

## 8. Network Performance: Bandwidth, Throughput & Goodput

### Ethernet Rated (Link) Speeds
The link speed is the maximum transmission capability supported by the NIC or switch port:
- **10 Mbps:** Standard Ethernet (legacy)
- **100 Mbps:** Fast Ethernet
- **1 Gbps:** Gigabit Ethernet (standard desktop/LAN speed)
- **2.5 Gbps / 5 Gbps:** Multi-Gigabit Ethernet
- **10 Gbps:** 10-Gigabit high-performance Ethernet

> [!NOTE] Transfer Time Calculation
> **Question:** If you transfer a $5\text{ Mb}$ (megabit) audio file over a link operating at $1\text{ Mbps}$, how long does it take?
> $$\text{Transfer Time} = \frac{\text{File Size}}{\text{Link Speed}} = \frac{5\text{ Mb}}{1\text{ Mbps}} = 5\text{ seconds}$$

### Bandwidth vs. Throughput vs. Goodput

$$\text{Theoretical Bandwidth} \ge \text{Throughput} \ge \text{Goodput}$$

```text
┌───────────────────────────────────────────────────────────────────────┐
│ Theoretical Bandwidth (Rated capacity: "Width of Highway")            │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │ Throughput (Actual transmitted bits = Payload + Headers/Delays) │  │
│  │  ┌───────────────────────────────────────────────────────────┐  │  │
│  │  │ Goodput (Useful application data only: "Passenger delivery")│  │  │
│  │  └───────────────────────────────────────────────────────────┘  │  │
│  └─────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────┘
```

1. ==**Theoretical Bandwidth:**==
   - The absolute maximum possible data rate supported by the physical technology under ideal theoretical conditions.
   - *Highway Analogy:* The physical width and maximum lanes of the highway.
   - *Fuel Analogy:* Manufacturer claims a car achieves $15\text{ km/L}$ on a test track.
2. ==**Throughput:**==
   - The actual rate at which data signals cross the transmission medium in practice.
   - Reduced below bandwidth by protocol framing overhead, packet collisions, retransmissions, processing latency, and network congestion.
   - *Formula:* $\text{Throughput} = \text{Useful Data} + \text{Protocol Overhead}$.
   - *Highway Analogy:* How many total vehicles are actually moving down the highway.
3. ==**Goodput (Good Throughput):**==
   - The actual rate at which the **useful application payload** (the data the user truly cares about, excluding packet headers and retransmissions) is successfully delivered to the destination.
   - Goodput typically reaches approximately **70% – 80%** of theoretical bandwidth.
   - *Example:* If an ISP advertises a $10\text{ Gbps}$ plan, the expected real-world goodput is:
     $$10\text{ Gbps} \times 70\% \text{ to } 80\% \approx 7\text{ to } 8\text{ Gbps}$$

## 9. LAN Services & Network Expansion

A basic switched LAN enables sharing diverse local resources and services:

```text
                        ┌──────────────────┐
                        │ Network Printer  │ (Static IP)
                        └────────┬─────────┘
                                 │
 [PC 1] ────┐                    │                    ┌──── [Laptop]
            │             ┌──────┴───────┐            │
 [PC 2] ────┼─────────────┤    SWITCH    ├────────────┼──── [Smartphone (Wi-Fi)]
            │             └──────┬───────┘            │
 [PC 3] ────┘                    │                    └──── [Backup Server / Nginx]
                                 │
                        ┌────────┴─────────┐
                        │ Wireless Router  │
                        │ (Switch + AP + R)│
                        └──────────────────┘
```

1. **Shared Peripherals:**
   - Network printers assigned dedicated, static IP addresses allow multiple client computers to print concurrently across the LAN.
2. **Centralized File & Backup Servers:**
   - Instead of storing files locally across individual workstations (risking permanent data loss if a client PC crashes), a dedicated local server can be added to the switch.
   - Devices can run automated periodic backups to the server, and authorized local users can access centralized files from anywhere in the local premises.
3. **Client-Server Architecture:**
   - Workstations act as clients requesting services from dedicated host servers (e.g., local **Nginx** web servers hosting internal tools or web apps).
4. **Wireless LAN (WLAN) & Integrated Routers:**
   - To connect wireless devices (smartphones, laptops, tablets) without running physical cables, networks deploy **Wireless Routers**.
   - A consumer wireless router integrates three distinct devices into a single chassis:
     - An **Ethernet Switch** (for wired LAN connections).
     - A **Wireless Access Point (AP)** (converting Ethernet frames into radio frequencies).
     - A **Router** (handling traffic routing between networks).
   - **IEEE Standards:** Ethernet follows the IEEE 802 family:
     - `802.3`: Wired Ethernet standard.
     - `802.11`: Wireless Wi-Fi standard. Letter designations (e.g., $802.11\text{a/b/g/n/ac/ax}$) indicate operating transmission range and supported bandwidth (essential for streaming HD/UHD multimedia).

## 10. The Internet: "The Network of Networks"

- **Beyond the LAN Boundary:** A LAN provides local file and device sharing, but cannot reach external networks on its own.
- **The Interstate Highway Analogy:**
  - Driving inside your local neighborhood street is like communicating within your LAN.
  - To travel from **Sydney to Canberra**, you must leave your local street and merge onto an interconnected regional and national highway system.
- ==**The Internet:**== An abbreviation for **Inter-connected Networks** ("a network of networks").
- ==**Router ($R$):**==
  - The gateway device that joins individual LANs together.
  - Inspects destination IP addresses to route packets across intermediate networks until they reach their remote destination LAN.

```text
 ┌─────────────┐                                           ┌─────────────┐
 │  Local LAN  │                                           │  Remote LAN │
 │  (Sydney)   │───[Router R1]───[ THE INTERNET ]───[Router R2]───│  (Canberra) │
 └─────────────┘                 (Interconnected)          └─────────────┘
                                    Backbones
```
