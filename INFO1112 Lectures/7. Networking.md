## 1. What is a Network?

- ==**A Computer Network**== is a collection of **two or more devices connected together to share resources**.

### Key Network Concepts
- **Device ([[Node]]):** Any electronic equipment that can connect to a network (e.g., classroom desktop computers, laptops, smartphones, tablets, network printers, servers, IoT devices).
- **Transmission Medium (Media):** The physical or wireless path connecting devices:
  - **Wired:** Copper cables (Ethernet/Twisted Pair, Coaxial), Optical Fiber.
  - **Wireless:** Radio waves (Wi-Fi, Bluetooth, Cellular 4G/5G, Satellite).
- **Resources:** The digital data, services, or hardware shared across the network:
  - *Files and Data:* Documents, databases, game assets, audio/video streaming.
  - *Services & Applications:* Webpages, social media platforms (posts, messaging), APIs.
  - *Hardware:* Shared office printers (e.g., 20+ workstation computers sharing a single printer in J12 L3).
  - *Connectivity:* Sharing an Internet uplink (e.g., tethering a laptop to a smartphone's cellular data connection on a train).

## 2. The Five (5) Core Elements of a Network

Every communication network requires exactly **five fundamental components** to function:

```text
 ┌──────────┐                                                   ┌──────────┐
 │  Sender  │ ────[Message carried via Signal]────> │ Medium │ ────>│ Receiver │
 └──────────┘                                                   └──────────┘
      ▲                                                              ▲
      └──────────────────────[ Protocols ]───────────────────────────┘
```

1. ==**Sender:**== The device/source that creates and transmits the message or data request.
2. ==**Receiver:**== The destination device intended to receive the message or resource. (A network requires at least 2 devices).
3. ==**Message:**== The information or data being communicated (carried by an electromagnetic or optical **signal**). It can be the resource itself (e.g., a file) or a request for a resource.
4. ==**Medium:**== The physical or wireless communication channel through which the signal travels from sender to receiver.
5. ==**Protocols:**== The formal set of **rules and standards** governing the communication:
   - Dictates message syntax (formatting), semantics (meaning), encoding, language, error detection, and synchronization.
   - *Unlike humans, computers cannot make assumptions.* Before two devices can communicate meaningfully, they must agree in advance on the protocol (e.g., **IPv4**, **IPv6**, **TCP**, **HTTP**).

| Element | Role | Example |
| :--- | :--- | :--- |
| **Sender** | Initiator / transmitter of communication | Laptop requesting a web page |
| **Receiver** | Target recipient of communication | Web server responding with data |
| **Message** | Content or resource being sent | HTTP GET request / HTML page data |
| **Medium** | Physical channel carrying signals | Cat6 Ethernet cable, 5 GHz Wi-Fi radio |
| **Protocol** | Standardized rules governing transfer | IPv4 / IPv6, TCP/IP, Ethernet IEEE 802.3 |

## 3. Network Topology

- A **topology** is the blueprint, geometric layout, or structural template of a network.
- **Physical Topology:** The physical arrangement of cables, switches, and hardware devices in space.
- ==**Logical Topology:**== How data flows and how the network **behaves** logically, regardless of physical cabling layout.

### Ring Topology Example
- Devices (nodes) are arranged logically in a closed loop (circle).
- **Minimal condition:** 1 node alone is not a network; a network requires $\ge 2$ nodes.

```text
               (Node 1)
              /        \
             /          \
      (Node 3)          (Node 4)
             \          /
              \        /
               (Node 2)
```

#### How Data Flows in a Ring:
1. **Unidirectional Circulation:** Messages travel sequentially around the ring from neighbor to neighbor in a set direction (e.g., clockwise).
2. **Relay / Hop Behavior:**
   - Suppose **Node 1** wants to send a message to **Node 2** via **Node 4**.
   - The message reaches **Node 4** first.
   - Node 4 inspects the destination header: the **destination IP address** does not match Node 4.
   - Node 4 acts as a **relay**: it does not consume or modify the payload, but forwards the message along the ring to the next node.
3. **Security & Protocol Compliance:**
   - Protocol rules dictate that intermediate nodes must not intercept, alter, or read messages addressed to other nodes.
   - When the message reaches **Node 2**, the destination address matches Node 2's own IP address, and Node 2 processes the payload.

## 4. Media Access Control & Collisions

### What is a Collision?
- When two or more devices transmit signals simultaneously over the same shared transmission medium, the electrical or radio signals interfere and overlap.
- This creates a ==**collision**==, corrupting the message data so that neither transmission can be decoded.
- **Fundamental Rule of Shared Mediums:** When one node transmits, all other nodes sharing that medium must listen.

### Token Ring / Token Passing Media Control
- To prevent collisions on a ring or shared bus, networks implement **Media Access Control (MAC)** protocols.
- **The "Token" (Microphone) Analogy:**
  - A special control frame called a ==**Token**== circulates continuously around the network.
  - Think of the token as a *microphone* in a conference: **only the node currently holding the microphone is permitted to speak (transmit)**.
  - While Node 1 holds the token, no other node can initiate communication.
  - Once transmission is complete, the token is passed to the next downstream node (e.g., Node 4 $\rightarrow$ Node 2 $\rightarrow$ Node 3).
  - This ensures that only one device transmits at any instant, guaranteeing **0 collisions**.

```text
[Node 1] holds Token (Microphone) ──> Transmits data frame
[Node 4] Listens & relays
[Node 2] Receives destination packet
[Node 3] Listens
Token is released and passed to downstream neighbor
```

## 5. Traffic Control Analogies for Media Access

Road traffic management systems reflect how networks regulate shared channel access:

| Traffic Control Scheme | Network Analogy | Behavioral Characteristics | Best Used For |
| :--- | :--- | :--- | :--- |
| **Traffic Lights** | Scheduled / Ring access | Alternating deterministic turns (Green = Go, Red = Stop); nodes wait for their slot. | High volume / dense networks |
| **Stop Signs** | Strict turn-taking (Polite CSMA) | Every vehicle stops, checks for competing traffic, waits 3 seconds, and takes turns one by one. | Low volume / simple intersections |
| **Roundabouts** | Continuous flow with give-way rules | Vehicles yield to traffic already circulating inside; maintains smooth, steady movement without complete halts. | Balanced, continuous traffic flow |

### Network Scaling & Collisions
- **The Scaling Challenge:** As the number of nodes/users on a network grows, the volume of messages generated increases exponentially.
- Without coordination protocols, higher message density leads to frequent collisions, packet retransmissions, and severe performance degradation.
- **Protocol Importance:** Strictly enforced protocols eliminate chaos:
  $$\text{Strict Protocol Adherence} \implies \text{Zero Collisions \& Reliable Delivery}$$
