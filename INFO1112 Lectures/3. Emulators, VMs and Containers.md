## UID (User ID)/ GID(Group ID)
- A process is a program with its data stored in memory, as well as metadata like owner, open files etc.
- Every Process running has an associated User ID 
- When a process is ran by the shell, it uses the UID of the shell
		- The commands run can access the same files the user has access to, or anything the users group has access to
- ==**/etc/passwd**== file contains translation/mapping between the User ID's used by UNIX kernel, and the Usernames

- ==**/etc/group**== file contains the mapping between the UNIX kernels GID and the group name
- Groups are used to manage permissions to multiple users at once, instead of individually assigning permissions
- Every user in a group has the same permissions as the group, even if their individual user permissions are lower
- **When an account gets created, it also gets assigned to a group of the same name**

```bash
$ cat /etc/passwd
root:x:0:0:root:/root:/:/bin/bash
riley:x:1000:1000::/home/riley:/bin/bash

#UserID: 1000
#GroupID: 1000
#Home directory is /home/riley
#Shell program is at /bin/bash

$ cat /etc/group
root:x:0:
riley:x:1000

#To find the id of UID of the Shell we can use:
$ id
uid=1003(riley) git=1003(riley) groups=1003(riley)
```

## SuperUser ID
- **UID 0** is very special, it has access to any file and can run any program 
	- Also can access any device, as devices are just files in the [[Namespace]]
- Superuser is given the username **root** since this is the first process that is executed by the system
- superuser is very powerful, but also dangerous

## Devices in the [[Namespace]]
- Feature of UNIX was to make access to devices similar to other files
	- Every device is also a file in the namespace
	- Standard read/write/execute/open/close system calls work in the same way for devices as with normal files
- On a UNIX system, the ==**/dev/sda**== is the pathname for the disk drive
	- By opening and reading this, you can access the whole device starting from there\
	- Often needs superuser permissions to access
```bash
$ ls -l /dev/sda
brw-rw---- 1 root disk 8, 0 Jun 23 13:04 /dev/sda
```

## Emulator
- An emulator is a program that reads machine instructions (binary) and interprets or executes them, pretending to be a real CPU.
- It "emulates" instructions, running a program designed for one architecture on another.
- It translates Assembly language into binary machine code using an **Assembler**.
- Decoding process: It uses bitwise operations like **right shifting** (to extract parts of the instruction) and **masking** (using logical AND with a bitmask) to extract opcodes and operands.
- While emulators provide insights into system mechanisms, emulated programs generally run very slowly.

## Virtual Machine (VM)
- A VM is a complete emulation capable of running an entire operating system (OS) with memory management and I/O.
- Allows you to run a different OS (e.g., Linux on Windows), run older software, and develop/test across various environments.
- Provides complete isolation for the running applications.
- **Downsides**: High resource utilization, consumes higher disk space (GBs in size), and has a slower "boot up" time because it has to boot an entire OS.
- Example: VirtualBox by Oracle.

## Container
- Containers provide isolated environments (processes, network interfaces, mounts) much like VMs.
- **Difference from VMs**: All containers on a host share the **same OS kernel** (e.g., Linux kernel) responsible for interacting with the hardware.
- It is the software above the kernel (user interfaces, drivers, compilers) that makes them different.
- **Advantages**: Because they share the kernel and don't boot a full OS, containers are very lightweight (MBs in size) and have a much faster boot-up time.
- Example: Docker. You can run multiple flavours of Linux containers on a single Ubuntu host, but you cannot run a Windows-based container on a Linux host because they do not share the same kernel.
