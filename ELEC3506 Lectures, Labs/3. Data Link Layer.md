# 1. Data Link Layer Overview & Services

- **Role**: Ensures reliable hop-to-hop frame delivery between adjacent nodes across a single physical link.
- **Core Services**:
	- **Framing**: Packages network datagrams with header (MAC addresses, control) and trailer (error check).
	- **Media Access Control (MAC)**: Coordinates access to shared broadcast media.
	- **Flow Control**: Matches transmission speed to receiver buffer capacity.
	- **Error Control**: Detects and handles corrupted/lost frames (FEC or ARQ).
- **Implementation**: Embedded in the **Network Interface Card (NIC)** or chipset; spans hardware, firmware, and OS device drivers connected via host bus (PCIe).
- **IEEE 802 Sublayers**:
	- **LLC (Logical Link Control / 802.2)**: Upper sublayer; standardizes interface to Network layer, handling flow and error control.
	- **MAC (Media Access Control / 802.3, 802.11)**: Lower sublayer; manages physical channel access and hardware MAC addressing.

# 2. Framing & Bit Stuffing

- **Framing Approaches**:
	- **Fixed-Size**: Uniform frame lengths (e.g., ATM 53-byte cells); simple boundary detection.
	- **Variable-Size**: Varying lengths (e.g., Ethernet); requires explicit delimiters.
- **Delineation Methods**:
	- **Byte-Oriented**: Framing flags with **byte stuffing** (escape characters `ESC` prepended to data mimicking flags).
	- **Bit-Oriented & Bit Stuffing**:
		- Uses delimiter flag pattern: `01111110` (six consecutive $1$s).
		- **Sender Rule**: Inserts a stuffing `$0$` immediately after any sequence of five consecutive $1$s (`11111`) in the data payload.
		- **Receiver Rule**: When five consecutive $1$s are followed by `$0$`, the `$0$` is stripped. If followed by a `$1$`, it signals the frame flag.

# 3. Error Detection & Redundancy

- **Error Types**: Single-bit errors (1 bit flipped) vs. Burst errors ($\ge 2$ clustered bits flipped).
- **Code Rate**: $R = k/n$, where $k$ is data bits and $n$ is total codeword length ($k$ data $+ (n-k)$ parity bits). Lower rate = stronger error protection but reduced throughput.

### Common Detection Techniques
- **Parity Checking (VRC)**: Appends 1 bit per byte for even or odd parity. Fails on even numbers of bit flips (~50% reliability).
- **Longitudinal Redundancy Check (LRC)**: 2D block parity over rows and columns; detects multi-bit errors.
- **Internet Checksum**: 1's complement arithmetic sum over 16-bit blocks (used in IP/TCP/UDP).
- **Cyclic Redundancy Check (CRC)**:
	- Grounded in modulo-2 polynomial division (bitwise XOR without carries).
	- Uses a generator polynomial $g(x)$ of degree $n - k$ (length $n - k + 1$).
	- **Encoding**: Append $(n - k)$ zeros to message $u(x)$, divide by $g(x)$, and append remainder $b(x)$ to form codeword $v(x) = u(x)x^{n-k} + b(x)$.
	- **Decoding**: Divide received codeword by $g(x)$. Remainder $= 0 \implies$ valid frame; non-zero remainder $\implies$ error detected.
	- **Example Walkthrough**:
		- Divisor $g(x) = x^3 + x + 1$ (`1011`), Message $u(x) = x^3 + 1$ (`1001`), $k=4, n=7$.
		- Modulo-2 division of $1001000$ by $1011$ gives remainder $b(x) = x^2 + x$ (`110`).
		- Transmitted Codeword: `1001110`.
	- **Detection Power**: Detects all single-bit, double-bit, odd-numbered errors, and all burst errors of length $\le n - k$.

# 4. Error Correction & Flow Control

- **Forward Error Correction (FEC)**:
	- Receiver autonomously reconstructs corrupted bits from redundancy bits without retransmission.
	- **5G NR Applications**: **LDPC** for data channels (high throughput); **Polar Codes** for control channels (optimal at short block lengths).
- **Automatic Repeat reQuest (ARQ)**:
	- Retransmission protocol combining error detection with Positive ACKs, Negative NAKs, and retransmission timers.

# 5. Point-to-Point Protocol (PPP)

- Byte-oriented Data Link standard for dedicated point-to-point WAN and dial-up links.
- **Frame Structure**:
	- `Flag (01111110)` (1B) $\to$ `Address (11111111)` (1B broadcast) $\to$ `Control (00000011)` (1B unnumbered) $\to$ `Protocol` (1–2B payload type) $\to$ `Payload` $\to$ `FCS` (2–4B CRC) $\to$ `Flag` (1B).
	- Note: PPP provides no built-in flow control.

# 6. Interconnecting Devices & Bridging

### Layer 1 vs. Layer 2 vs. Layer 3
- **Passive Hub (L1)**: Physical bus repeating electrical signals to all ports. Single collision domain and single broadcast domain.
- **Repeater / Active Hub (L1)**: Regenerates pristine digital signals, stripping noise (unlike analog amplifiers, which amplify noise).
- **Bridge / Switch (L2)**: Connects segments; isolates collision domains; makes forwarding decisions using MAC addresses.
- **Router (L3)**: Forwards packets between different subnets based on IP addresses; isolates broadcast domains.

### Transparent Bridges & Backward Learning
- Bridges start with empty forwarding tables and dynamically learn station locations:
	1. **Learning**: Reads the **source MAC address** and incoming port of every arriving frame; caches mapping in table.
	2. **Filtering / Forwarding Decision**:
		- Destination MAC on same port $\to$ **Discard/Filter** frame.
		- Destination MAC on known different port $\to$ **Forward** out that port only.
		- Destination MAC unknown $\to$ **Flood** frame out all ports except arrival port.

### Bridging Loops & Spanning Tree Protocol (STP / IEEE 802.1D)
- **The Problem**: Redundant physical links create network loops, causing broadcast storms and MAC table instability (thrashing).
- **STP Solution**: Dynamically disables redundant links to create a loop-free logical tree:
	- Bridges exchange **BPDUs (Bridge Protocol Data Units)**.
	- **Root Bridge Election**: Switch with the lowest Bridge ID (Priority + MAC address; default priority in multiples of 4096).
	- **Port States**: **Blocking $\to$ Listening $\to$ Learning $\to$ Forwarding**.

### Switches & Forwarding Methods
- A switch is a high-speed multiport bridge providing dedicated full-duplex bandwidth per port.
- **Cut-Through Switching**: Reads only the destination MAC address (first 6 bytes) and forwards immediately. Lowest latency, but forwards corrupted frames.
- **Store-and-Forward Switching**: Buffers the entire frame and verifies the CRC/FCS before forwarding. Adds latency, but eliminates error propagation.

# 7. Address Resolution Protocol (ARP)

- **Purpose**: Dynamically resolves a known 32-bit logical IP address to its corresponding 48-bit physical MAC address on the local network.
- **Mechanism**:
	1. **ARP Request (Broadcast)**: Sent to MAC `FF:FF:FF:FF:FF:FF`: *"Who owns IP $X$? Reply to MAC $Y$."*
	2. **ARP Reply (Unicast)**: Target node matching IP $X$ replies directly with its MAC address.
	3. **ARP Cache**: Both nodes save the mapping in their local ARP cache table to avoid repeated queries.
